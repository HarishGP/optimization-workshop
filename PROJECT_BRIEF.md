# Project Brief

## Overview
This project supports a 2-hour hands-on workshop for undergraduate students with basic Python and introductory machine learning background.

The workshop uses small PyTorch examples to explain how optimization algorithms behave during neural network training. The emphasis is conceptual understanding, visual intuition, and lightweight experimentation on student laptops.

## Audience
- Undergraduates with basic Python familiarity.
- Some exposure to machine learning concepts is helpful.
- Students are not assumed to know PyTorch in depth.

## Teaching goals
The workshop should help students:
- Understand gradient-based optimization in neural networks.
- Compare SGD, momentum, AdaGrad, and Adam.
- See how optimizer behavior changes across different settings.
- Build intuition for convergence speed, stability, and sensitivity to learning rate.
- Experiment with models and data through notebooks.

## Project objective
Simulate optimization algorithms and demonstrate their advantages and trade-offs in different settings using small, CPU-friendly fully connected networks.

## Scope
In scope:
- Small synthetic datasets.
- Fully connected networks.
- Simple loss curves and training visualizations.
- Notebook-driven experiments.
- Clear helper modules for data generation, model setup, and optimization logic.

Out of scope:
- Large datasets.
- GPU workflows.
- Complex training infrastructure.
- Production packaging.
- Advanced MLOps or deployment concerns.

## Design principles
- Keep setup simple for students.
- Keep runtime short on ordinary laptops.
- Prefer conceptual clarity over realism.
- Make code easy to inspect and modify.
- Separate stable helper code from exploratory notebook code.

## Success criteria
A successful version of this project should:
- Install reliably with minimal friction.
- Run on CPU-only student laptops.
- Let students complete the main notebook flow within the workshop time.
- Make optimizer differences visible in plots or metrics.
- Leave room for optional exploration by stronger students.

## Notes for coding agents
When proposing changes:
- Optimize for teaching value first.
- Keep dependencies lean.
- Avoid restructuring imports in a way that makes notebooks harder to run.
- Prefer incremental improvements over major redesigns.
- Preserve a clear boundary between student-facing notebook code and helper-library code.


## First phase:

The goal is to run simple gradient descent, adagrad, gradient descent with momentum, Adam and finally MuON over various optimisation objectives and show their advantages and illustrate the differences in the trajectory. 

Firstly use simple low dimensional (2 or at most 3-dimensional) objective functions to illustrate the concepts graphically.
